# Phase J-Q1 — Audit Log Contract Architecture Hardening

**Date:** 2026-05-23
**Focus:** Contract Decoupling & DB Immutability

## Architectural Changes
1. **Decoupled Packages:** 
   - Removed Drizzle ORM dependencies and persistence definitions from `@santis/domain-schema`.
   - `@santis/domain-schema/src/audit-log.contract.ts` now strictly contains canonical Zod schemas and TypeScript types.
2. **Schema Location:**
   - Drizzle schema is temporarily located in `apps/ingestion-api/src/db/schema/audit-logs.ts` as technical debt until a dedicated `@santis/database` package is spun up.
3. **Actor Operator ID:**
   - Updated `actorOperatorId` to strictly accept UUIDs, aligning with Supabase `auth.users.id`.
   - Test suites were updated to pass valid UUIDs in `sub`.
4. **Data Privacy & Schema Rules:**
   - `tenantId` is a required UUID.
   - Raw `ipAddress` and `userAgent` are excluded.
   - `ipHash` and `userAgentHash` are constrained to 64-char `varchar` for SHA-256 hex encoding.
   - `resourceId` is nullable and optional.
   - `payloadJson` defaults to `{}`.

## Database Immutability Plan (CoreState SSOT)
To strictly enforce an **append-only** architecture for audit logs:

1. **Application-Level:**
   - The Audit Log repository must strictly expose `create` and `query` methods.
   - No `update` or `delete` methods shall be implemented in the repository pattern.
2. **Database-Level (PostgreSQL):**
   - **RBAC:** The application role/user (e.g., `authenticator` or backend connection role) must only be granted `INSERT` and `SELECT` privileges on the `audit_log_events` table. `UPDATE` and `DELETE` privileges must be explicitly revoked or never granted.
   - **Generation:** `created_at` must only be generated by the database via `defaultNow()` and never mutated.
   - **Trigger (Optional Future Hardening):** A PostgreSQL `BEFORE UPDATE OR DELETE` trigger can be added to explicitly `RAISE EXCEPTION 'Audit logs are immutable'` to guarantee zero accidental mutations by superusers.
